Data & Method
What happens to the raw tracking files, in nine steps
  1. 1Load the file

    One CSV per period, loaded straight into a table with every column as text. The periods present in the drop are the periods that get loaded; some games are missing part of the third and the whole of overtime.

  2. 2Unpack the image id

    Image Id packs the game, the teams and the frame into one string: 2025-11-28 Team J @ Team K_065468. The first 26 characters are the game id, which is also how the event file builds its game id, and the last six are the frame number.

  3. 3Turn the clock into a running total

    The clock counts down and restarts every period, so it is replaced with time_elapsed: seconds since the opening faceoff. Period 2 starts at 1,200 and overtime at 3,600, which is the same frame the event file uses, so the two can be joined on time.

    About one row in a thousand has no clock at all. Those rows cannot be placed in time and are dropped, and the count of them is kept.

  4. 4Face the rink one way

    Teams change ends between periods, so a position from period 1 and the same position from period 2 are mirrored. The camera table says which team had its goalie on the right in the first period, and the periods where that makes the home end the wrong way are mirrored back.

  5. 5Put the puck in every row

    The puck is a row like any other. Its position is joined onto every player in the same frame, which is what makes the next step possible: distance to the puck, by Pythagoras.

  6. 6Find who is holding it

    The player nearest the puck is ranked first, and a player must also be within six feet of it to be given possession. Six feet is about a stick length: nearer than that and the puck is at their feet, further away and it is loose.

    That gives player_in_possession and team_in_possession, and the same ranking within a team gives distance_rank_team.

  7. 7Name the defenders

    On frames where the other team has the puck, a defender is Primary if they are the nearest defender or within six feet of the puck, and Secondary otherwise. It separates the player actually pressuring the puck from the ones holding shape.

  8. 8Attach the state of the game

    Neither file has strength or score in the tracking data, so both come from the event file: the strength state and the score are turned into windows with a start and an end, and each frame is matched to the window it falls in.

    A game returns to strength states it has already been in, so the windows are numbered spells rather than grouped by state. Grouping by state folds every 5v5 spell into one and then most of the game carries the wrong label.

  9. 9Index it

    The table is keyed on (image_id, player_id), which is one row per player per frame and is unique in the data. Two secondary keys carry the queries the pages make: a game plus a time range, and one player across a game.

Things worth knowing before trusting a number
WhatWhy it matters
player_id is a track, not a person The tracker re-issues ids when it loses and re-acquires a player: {{ "{:,}".format(meta.track_ids) }} ids for {{ meta.players }} players in this game, 132 of them on the goalie alone. Anything per player groups on (team, jersey).
Goalies are marked Go The jersey column holds Go instead of a number for goalies, and blanks for players whose number was not read. It is the only goalie marker in the data, so it is carried into an is_goalie column rather than cast away.
Blank and n/a are different things Puck rows carry n/a in the team and id columns and blanks in the coordinates. Both mean "not applicable", and both have to become NULL rather than zero before the columns can be typed.
Not every player is in every frame Around eight players per frame instead of ten skaters and a goalie, so a count is "seen here", not "was here".
Overtime ends The mirroring treats overtime like period 2. Worth confirming by eye for each game, because it decides whether overtime is mirrored.
